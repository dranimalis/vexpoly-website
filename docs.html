Install

The recommended way to play is a pre-built binary from the download page — no Python install needed. If you'd rather run from source, you'll need Python 3.9 or newer. 

git clone https://github.com/dranimalis/vexpoly.git
cd vexpoly
python3 -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt

The only hard dependency is pygame-ce 2.5 or newer. All other modules come from the Python standard library.

Running the game

python vexpoly.py

Settings and progression records are saved as vexpoly_save.json in your per-user data directory:

  • Windows: %LOCALAPPDATA%\VEXPOLY\vexpoly_save.json
  • macOS: ~/Library/Application Support/VEXPOLY/vexpoly_save.json
  • Linux: $XDG_DATA_HOME/vexpoly/vexpoly_save.json when XDG_DATA_HOME is an absolute path; otherwise ~/.local/share/vexpoly/vexpoly_save.json.

If a newer settings file does not exist, VEXPOLY checks for the legacy vexpoly_save.json beside the source or bundled application and migrates it by saving a copy to the user data directory. Settings are not stored in a configurable key-binding file.

Project structure

The game is currently a single-file Python application with bundled runtime assets and a small test suite: 

vexpoly/
├── vexpoly.py             # renderer, gameplay, UI, and audio
├── requirements.txt       # pygame-ce dependency
├── pyproject.toml         # package metadata and asset installation
├── vexpoly.spec           # PyInstaller release build
├── README.md
├── CHANGELOG.md
├── tests/
├── .github/workflows/     # CI and release automation
└── assets/
    ├── textures/
    │   ├── _shared/
    │   └── <theme>/
    ├── sounds/
    └── ui/

The writable save file is kept outside the repository in the per-user data directory described above. Older saves found beside the application are migrated on load.

How the renderer works

Every frame walks the same eight stages. Nothing is handed to a GPU.

1. Camera transform

Each world vertex is translated into view space using the camera's yaw and pitch. The result is a coordinate relative to the camera.

2. Near-plane clipping

Polygons that cross z = near are cut against the plane before projection. Without this step, faces flip inside out when they pass behind the camera.

3. Perspective projection

A single divide by camera-space depth turns each vertex into a screen coordinate.

4. Backface and frustum culling

Faces pointing away from the camera are dropped early. So are faces entirely outside the view rectangle.

5. Directional lighting

One fixed light vector. One dot product per face. A flat Lambertian shade, no specular.

6. Distance fog

Camera-space depth feeds a simple exponential curve that fades each face toward the sky colour.

7. Depth sort

Visible faces are sorted by average camera-space depth, back to front. This is painter's algorithm — cheap and correct enough for the scale the game plays at.

8. Draw

Each face becomes one call to pygame.draw.polygon. That's the entire draw path.

Themes

A theme in VEXPOLY is not a tint. It swaps:

  • The sky gradient
  • The fog colour and curve
  • The light direction
  • The colour grade applied to lit faces
  • The entire texture set

Five themes ship with the game: Industrial, Void, Crimson, Arctic, and Toxic. You can preview each one on the homepage.

Troubleshooting

macOS says VEXPOLY can't be opened

The macOS builds are unsigned, so Gatekeeper blocks them on first launch. To allow the app, open System Settings → Privacy & Security, scroll down to the "VEXPOLY was blocked" notice, and click Open Anyway.

Or remove the quarantine flag directly in Terminal:

xattr -dr com.apple.quarantine /Applications/VEXPOLY.app

You only need to do this once. After that the app opens normally.

Windows SmartScreen blocks the .exe

The Windows build is unsigned. On first launch SmartScreen shows a "Windows protected your PC" dialog. Click More info, then Run anyway.

The window opens but nothing renders

You're likely running an old pygame instead of pygame-ce. Uninstall the former, then install the latter: 

pip uninstall pygame
pip install pygame-ce

Linux AppImage won't start

If you get a FUSE error, either install libfuse2: 

sudo apt install libfuse2          # Debian / Ubuntu
sudo dnf install fuse-libs         # Fedora

Or extract the AppImage instead of mounting it:

./vexpoly-x86_64.AppImage --appimage-extract
./squashfs-root/AppRun

Low framerate

Open the in-game Settings menu and make sure ADAPTIVE RES is enabled. VEXPOLY adjusts render scale and its polygon budget automatically; the configured budget is 1,800 polygons, with adaptive limits from 900 to 4,000. There is no user-editable config file for changing the polygon budget.

If performance is still poor, close other demanding applications and try running the game in a smaller window.

Sound is distorted on Linux

Set the SDL audio driver to pulseaudio before launching: 

SDL_AUDIODRIVER=pulseaudio python vexpoly.py
